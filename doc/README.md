# 시연 영상 시나리오

> **목적**: 예선 제출용 시연 영상을 찍을 때 쓸 실행 순서와 테스트 케이스를 정리한다. 온보딩 3건을 준비해 온보딩→진단→재질문→리포트→초안→알림→재매칭까지 이 서비스의 기능을 빠짐없이, 논리적인 순서로 보여주는 걸 목표로 한다.
> **근거**: 여기 담긴 화면·API·조건 분기는 전부 실제 코드(`apps/web/app/onboarding/page.tsx`, `apps/api-core`, `apps/ai-engine`) 기준으로 확인한 값이다.

---

## 0. 사전 준비 체크리스트

- [ ] `docker compose ps`로 5개 컨테이너(web·api-core·ai-engine·postgres·chroma) 모두 정상 기동 확인
- [ ] `curl localhost:8080/api/agent/collect/status`로 실 정책자금 데이터가 충분한지 확인(seedOnly:false, realCount 1000건 이상 권장)
- [ ] `MOCK_LLM=false` 확인 — 실제 Claude 응답으로 시연해야 진단문·근거·리포트 문장이 매번 자연스럽게 나온다(MOCK 모드는 `[MOCK]` 접두사가 그대로 노출됨)
- [ ] 카카오 알림까지 보여줄 계획이면 카카오 로그인 테스트 계정을 미리 준비해둔다
- [ ] 케이스 1은 신규 회원가입 계정으로 진행해 "빈 대시보드 → 첫 상담"의 처음 경험을 그대로 보여준다

> **사업자등록번호 입력(국세청 자동조회) 화면은 이번 시연에서 다루지 않는다** — 추후 제거 예정 기능이라, 세 케이스 모두 업종·지역 등을 처음부터 수동으로 선택하는 경로로 진행한다.

---

## 1. 온보딩 테스트 케이스 3가지

세 케이스는 각각 다른 기능을 부각하도록 설계했다 — ①은 표준 해피패스(전체 흐름을 처음 끝까지 매끄럽게), ②는 지역 다양성과 대환 분기, ③은 조건부 꼬리질문·리스크 경고를 몰아서 보여준다.

### 케이스 1 — 카페 사장님 (서울 마포구) · 표준 해피패스

| 항목 | 입력값 |
| --- | --- |
| 업종 | 카페/디저트 (수동 선택) |
| 지역 | 서울특별시 / 마포구 |
| 운영기간 | 1~3년 |
| 직원수 | 1~4명 |
| 연 매출 | 5천만~1억 |
| 세금체납 | 없음 |
| 연체 | 없음 |
| 정책자금 수혜 이력 | 없음 |
| 자금 용도 | 시설 |
| 희망 금액 | 1천만~5천만 |

**보여주는 것**: 온보딩 9문항 전체 플로우, 콜1 진단→재질문 스텝위저드→카카오 동의→콜2 리포트까지 막힘없이 이어지는 기본 골든 패스.

### 케이스 2 — 숙박업 사장님 (충남 논산시) · 지역 확장성 + 대환 분기

| 항목 | 입력값 |
| --- | --- |
| 업종 | 숙박업 (8지선다 직접 선택) |
| 지역 | 충남 / 논산시 |
| 운영기간 | 3~7년 |
| 직원수 | 5~9명 |
| 연 매출 | 1억~3억 |
| 세금체납 | 없음 |
| 연체 | 있었지만 해결 |
| 정책자금 수혜 이력 | 상환 중 |
| 자금 용도 | **대환** 선택 → 꼬리질문 "지금 대출 금리가 대략 몇 %인가요?" 등장 → **7% 이상** 선택 |
| 희망 금액 | 5천만~1억 |

**보여주는 것**: 복수선택 자금용도 중 "대환" 선택 시에만 뜨는 금리 확인 꼬리질문, 그리고 **수도권이 아닌 지방 소도시(충남 논산시)도 실제로 매칭이 잘 된다는 것** — 이건 시연 며칠 전 실제로 매칭 0건이 나오던 지역 하드필터 버그를 찾아 고친 케이스라, "실제로 검증된" 지역이라는 의미도 있다.

### 케이스 3 — 재창업 준비 중 사장님 (경기 수원시) · 조건부 꼬리질문 + 리스크 경고 몰아보기

| 항목 | 입력값 |
| --- | --- |
| 업종 | 서비스업 |
| 지역 | 경기 / 수원시 |
| 영업상태 | **③폐업(재창업 준비)** 선택 → "재창업 준비 중이신가요?" 관련 안내 확인 |
| 운영기간 | 2개월 미만 |
| 직원수 | 없음(혼자) |
| 월 매출(업력 1년 미만이라 월매출 질문으로 자동 전환) | 500만 미만 |
| 세금체납 | **잘 모름** → 꼬리질문 "세무서·시청 납부 독촉장을 받은 적 있나요?" 등장 → **ⓒ모름** 선택 |
| 연체 | **잘 모름** → 꼬리질문 "최근 3개월 안에 이런 일이 있었나요?" 등장 → **ⓒ연체 문자·전화 받음** 선택 |
| 정책자금 수혜 이력 | **없음** → 꼬리질문 "이것도 정책자금이에요, 받아보신 적 없나요?" 등장 → **ⓔ없음** 선택 |
| 자금 용도 | 운영 |
| 희망 금액 | 1천만 이하 |

**보여주는 것**: 재창업 트랙 분기, 체납·연체 "잘 모름" 선택 시 뜨는 확인용 꼬리질문 2종, 정책자금 수혜 이력 재확인 꼬리질문까지 — 온보딩의 조건부 분기 로직을 한 케이스에 몰아서 보여준다. 리포트에서는 리스크 신호가 있는 만큼 **유의사항(caveats)이 붙은 매칭 카드**가 어떻게 다르게(적합도 톤 다운, "먼저 확인하세요" 안내) 보이는지가 볼거리다.

## 2. 시연 순서

전체적으로 "① 처음 써보는 사람의 경험을 가장 깊게 보여준 뒤 → ② 반복 사용 시나리오는 빠르게 넘기며 차별점만 짚고 → ③ 시간이 걸리는 능동 알림 기능은 수동 트리거로 압축"하는 순서로 짰다. 예상 소요시간은 편집 전 촬영 기준이다.

| # | 화면/동작 | 보여줄 포인트 | 예상(분) |
| --- | --- | --- | --- |
| 1 | 랜딩 페이지(로그아웃) | 캐릭터 히어로 + 임베디드 로그인 카드. "기존 서비스는 검색해야 답을 준다"는 한 문장 내레이션과 함께 회원가입 | 0.5 |
| 2 | 회원가입 → 대시보드(첫 진입, 빈 상태) | "상담 진행하기" CTA가 화면에서 가장 눈에 띈다는 것 | 0.5 |
| 3 | **케이스 1** 온보딩 9문항 | 폐쇄형 질문지(선택형이라 응답률 확보), 전 문항 수동 선택으로도 매끄러운 흐름 | 2 |
| 4 | 콜1 진단 대기 → 진단문 확인 | Opus가 매출·업종·연체 등 실제 값만 근거로 진단문을 쓴다는 것 | 1 |
| 5 | 재질문 스텝위저드 응답 | 한 문항씩, 이미 답한 건 다시 안 묻는다는 것 | 1 |
| 6 | 카카오 알림 동의 (선택) | 동의 시점이 화면 하나로 통합돼 있다는 것 | 0.5 |
| 7 | 콜2 대기(진단문 유지) → 리포트 진입 | "빈 대기 화면"이 아니라 방금 본 진단문을 유지한 채 기다린다는 디테일 | 0.5 |
| 8 | **리포트 상세 — 핵심 시연** | 좌측 AI 분석 문서(sticky)+우측 매칭 카드(독립 스크롤), 카드 클릭 시 좌측 문서가 해당 문단으로 자동 스크롤+하이라이트되는 "연결" 인터랙션, 적합도 점수·근거 체크리스트 | 2 |
| 9 | 신청서 초안 생성 | 매칭 카드에서 초안 생성 클릭 → 4섹션(사업개요·신청사유·활용계획·기대효과) 자동 작성, "직접 제출은 사용자 책임"이라는 점 짧게 언급 | 1 |
| 10 | 알림 벨 확인 | 인앱 알림 도착(30초 폴링) + (연동했다면) 카카오톡 알림 화면 | 0.5 |
| 11 | **케이스 2** 온보딩 → 리포트 (빠르게) | 수동입력 경로 + 대환 꼬리질문만 짚고, 진단·재질문은 스킵하듯 빠르게 넘어가서 리포트 결과로 직행. **"지방 소도시도 잘 매칭된다"는 걸 리포트 화면에서 지역명(충남 논산시)과 매칭 근거("지역 일치")를 가리키며 명시적으로 언급** | 2 |
| 12 | 매시간 재매칭 시뮬레이션 | 실제로는 배치가 매시간 자동으로 돈다는 걸 말로 설명하고, 시연에서는 수동 트리거(`POST /api/agent/check/{profileId}`)로 즉시 재현. 케이스 2 리포트를 다시 열어 **새로 매칭된 카드에만 NEW 배지**가 붙고 기존 카드는 순서를 유지한 채 그대로 남아있는 걸 확인 — "누적 매칭 리스트" | 1.5 |
| 13 | **케이스 3** 온보딩 → 리포트 (빠르게) | 재창업 분기 + 체납/연체 "잘 모름" 꼬리질문만 짚고 빠르게 진행. 리포트에서 **유의사항 있는 카드의 톤 다운된 표현**을 케이스 1의 깨끗한 카드와 나란히 비교하며 차이를 강조 | 2 |
| 14 | 대시보드/질문 이력으로 마무리 | 대시보드로 복귀해 "빠른 현황"(질문지 3건·리포트 N건)이 실데이터로 갱신된 걸 보여주고, `/profiles` 목록에서 3개 프로필이 각자 리포트와 함께 남아있는 걸 훑으며 종료 | 1 |

**합계 약 16.5분(촬영 기준)** — 실제 편집본은 대기 화면·타이핑 구간을 잘라내 5~7분 내외로 압축하는 걸 권장한다.

## 3. 촬영 팁

- **대기 시간이 실제로 걸린다.** 콜1(Opus)·콜2(매칭+Sonnet 2회)는 각각 수십 초~2분 가까이 걸릴 수 있다. 통으로 찍고 편집에서 대기 구간을 타임랩스/컷으로 압축하는 걸 권장한다.
- **재질문 문항은 매번 조금씩 다르게 생성된다.** Opus가 그때그때 만들기 때문에 이 문서에 적힌 것과 토씨까지 같지는 않을 수 있다 — 시연 중 실제로 뜬 문항을 그대로 진행하면 된다.
- **12번(재매칭 시뮬레이션) 트리거 명령**: `curl -X POST localhost:8080/api/agent/check/{케이스2의 profileId}` — 화면 녹화 중 터미널을 같이 띄워서 "이 호출을 배치가 매시간 자동으로 대신 해준다"고 설명하면 능동형 구조를 자연스럽게 전달할 수 있다.
- **리포트 카드가 5건 미만으로 나올 수도 있다.** 실 데이터 기준이라 매칭 건수가 케이스마다 다르다 — 미리 한 번 리허설로 각 케이스의 실제 매칭 건수를 확인해두면 좋다.
