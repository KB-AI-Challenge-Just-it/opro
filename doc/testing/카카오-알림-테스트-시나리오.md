# 카카오톡 알림 수동 테스트 시나리오

**목적**: 이미 발급된 리포트를 실제로 파이프라인을 다시 돌리지 않고, "카카오톡 알림 받기"에 동의한 카카오 계정으로 즉시 재발송해서 카톡으로 실제 어떻게 오는지(문구·버튼·딥링크) 눈으로 확인한다.

**추가된 기능**:
- 백엔드: `POST /api/notifications/kakao-test?reportId={id}&profileId={id}` — 기존 `KakaoMemoSender`를 그대로 호출해 지정한 리포트를 카카오 "나에게 보내기"로 즉시 재발송한다. 새 파이프라인 실행 없이 발송 경로만 재사용한다.
- 프론트: `질문 상세` 화면(`/profiles/{id}`)의 "받은 리포트" 목록, 각 리포트 항목 아래에 **"카카오톡 테스트 발송"** 버튼 추가. 클릭하면 위 API를 호출하고 결과를 바로 화면에 표시한다.

---

## 사전 준비

1. `docker compose up` (또는 로컬 실행)으로 api-core(8080)·ai-engine(8000)·web(3000)·postgres 기동.
2. api-core에 카카오 앱 키가 설정돼 있어야 한다 — `.env` 또는 환경변수:
   - `KAKAO_CLIENT_ID`
   - `KAKAO_CLIENT_SECRET` (콘솔에서 client_secret 활성화한 경우만)
   - `KAKAO_REDIRECT_URI` (기본값 `http://localhost:8080/api/kakao/oauth/callback` — 카카오 개발자 콘솔의 Redirect URI 등록값과 반드시 일치해야 함)
   - 키가 비어 있으면 카톡 발송은 조용히 스킵되고 인앱 알림만 남는다(에러 아님) — 이 시나리오를 돌리기 전에 반드시 채워야 한다.
3. 테스트용 계정으로 로그인 → 온보딩을 최소 1회 완료해 `business_profile`을 만들고, 리포트가 최소 1건 존재해야 한다(없으면 `/profiles/{id}`의 "받은 리포트"가 비어 있어 테스트 버튼도 안 보임).

## 시나리오 A — 카카오 연동 전 상태 확인 (실패 케이스 먼저 확인)

1. `http://localhost:3000/profiles`에서 온보딩 이력 클릭 → `질문 상세` 페이지 진입.
2. "받은 리포트" 목록에서 리포트 카드 아래 **"카카오톡 테스트 발송"** 버튼 클릭.
3. **기대 결과**: "카카오톡 연동이 안 되어 있습니다 — 먼저 카카오 알림 받기에 동의해주세요" 문구가 빨간색으로 표시됨.
   - 이 케이스는 아직 `kakao_token` row가 없을 때(온보딩 중 카카오 동의를 안 한 경우) 정상 동작이다. `KakaoMemoSender`가 미동의 프로필은 `notification_delivery` row 자체를 남기지 않으므로, 백엔드가 이를 `NOT_CONNECTED`로 구분해 응답한다.

---

## 시나리오 B — 카카오 연동 후 실제 발송 확인 (핵심 시나리오)

1. 온보딩 플로우 중 "카카오톡 알림 받기" 버튼(온보딩 페이지 하단)을 눌러 카카오 로그인 화면으로 이동 → 실제 카카오 계정으로 동의.
   - 동의 완료 시 `http://localhost:3000/?kakao=connected`로 리다이렉트되면 성공.
   - `kakao_token` 테이블에 `profile_id` 기준 row가 생겼는지 DB로 확인 가능: `SELECT * FROM kakao_token WHERE profile_id = {테스트 profileId};`
2. `/profiles/{id}`로 이동 → "받은 리포트" 목록에서 리포트 카드 하나 선택.
3. **"카카오톡 테스트 발송"** 버튼 클릭.
4. **기대 결과 (화면)**: 버튼이 잠깐 "발송 중..."으로 바뀌었다가, "카카오톡 발송 완료 — 카톡 앱에서 확인해보세요"(초록색)로 바뀐다.
5. **기대 결과 (카카오톡 앱)**: 발송에 사용한 카카오 계정의 "나에게 보내기" 채팅방에 아래 형태의 메시지가 도착해야 한다.
   - 텍스트: 알림 제목(`"[테스트] 카카오 알림 발송 확인"`)
   - 버튼: **"리포트 확인"** — 눌렀을 때 `{WEB_BASE_URL}/reports/{reportId}`로 정확히 이동하는지 확인.
6. 리포트 상세 페이지가 정상적으로 열리고, `/profiles/{id}`에서 조회했던 것과 동일한 본문(`bodyMd`)이 보이는지 확인.

**확인 포인트 (실제 서비스 알림과 동일한 경로인지)**:
- 이 버튼은 새 `notification` row를 만들고 `KakaoMemoSender.send()`를 그대로 호출하므로, 실제 배치/온보딩 트리거가 리포트를 보낼 때와 **동일한 카톡 템플릿·딥링크 로직**을 탄다. 즉 여기서 확인한 문구·버튼·링크 형태가 실제 서비스 알림과 100% 동일하다.
- `/api/notifications?profileId={id}&status=UNREAD`로 조회하면 테스트로 만든 알림도 인앱 알림 벨에 함께 뜨는지 확인 가능(의도된 동작 — 실제 발송 경로 재사용의 부작용).

## 시나리오 C — 토큰 만료/갱신 확인 (선택)

카카오 access_token은 통상 6시간 내외로 만료된다. 만료 임박(5분 이내) 상태에서 테스트 버튼을 누르면:
1. `KakaoMemoSender`가 `refresh_token`으로 자동 갱신을 시도한다.
2. 갱신 성공 시 `kakao_token.access_token`이 갱신되고 정상 발송(시나리오 B와 동일 결과).
3. 갱신 실패 시(예: refresh_token도 만료) 화면에 "발송 실패 — 토큰이 만료됐거나 카카오 API 오류입니다"가 표시된다 → 이 경우 온보딩 화면에서 카카오 연동을 다시 눌러 재동의해야 한다.

DB에서 강제로 만료 임박 상태를 만들어 테스트하려면:
```sql
UPDATE kakao_token SET expires_at = now() + interval '1 minute' WHERE profile_id = {테스트 profileId};
```

## 트러블슈팅

| 증상 | 원인 후보 | 확인 방법 |
|---|---|---|
| 버튼이 안 보임 | 해당 profile에 리포트가 하나도 없음 | `SELECT * FROM report WHERE profile_id = {id};` |
| 항상 NOT_CONNECTED | `kakao_token` row 없음 (동의 안 함) 또는 `KAKAO_CLIENT_ID` 미설정으로 OAuth 콜백이 애초에 실패 | api-core 로그에서 "카카오 토큰 교환/저장 실패" 검색 |
| SENT인데 카톡이 안 옴 | 카카오 "나에게 보내기" API는 개발자 콘솔에서 앱이 검수(사업자 등록/알림톡 아님) 없이도 테스트 계정 한정으로는 되지만, 콘솔에서 talk_message scope 미동의 시 조용히 실패할 수 있음 | 카카오 개발자 콘솔 → 내 애플리케이션 → 카카오 로그인 → 동의항목에서 "카카오톡 메시지 전송" 활성화 여부 확인 |
| FAILED | access/refresh 토큰 만료, 카카오 API 5xx | api-core 로그에서 "카카오 나에게 보내기 실패" 검색 (예외 메시지 포함) — `notification_delivery.error` 컬럼도 확인 가능 |
